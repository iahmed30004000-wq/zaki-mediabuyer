## 0) طريقة الشغل مع Claude Code

### 0.1 التجهيز (مرة وحدة)
1. اعمل مجلد مشروع فاضي `zaki-mediabuyer/`، وحط هالملف فيه باسم `docs/SPEC.md`.
2. افتح Claude Code بالمجلد، والصق **رسالة البداية** (تحت).
3. ولا مرة تلصق توكن أو مفتاح بالمحادثة. المفاتيح بتنحط بإيدك بملف `.env` على السيرفر.


### 0.3 كل جلسة بعدها

2. «نفّذ المهمة [الرقم] بس.» ← خطة قصيرة ← «تمام ابدأ».
3. بعد الاختبارات: تقرير عربي (شو انعمل · كيف أجرّب بإيدي · شو معلّق).

### 0.4 محتوى CLAUDE.md (Claude Code بيعمله بأول جلسة)
```
# Zaki Media Buyer
المرجع الوحيد: docs/SPEC.md. التقدم: docs/PROGRESS.md.
قواعد ما بتنكسر:
- الكود بيحسب كل رقم. الموديل بيفسّر بس، وما بيلمس ميتا ولا بيشوف توكن.
- كل تغيير على ميتا = ChangeSet (اقتراح ← تجهيز ← تجربة ← موافقة ← تنفيذ ← تحقق ← متابعة ← رجوع).
- القرار على حقيقة الـ OMS (مؤكد/مُسلَّم)، مش على Purchase ميتا لحاله.

- التجارب على حساب إعلاني تجريبي أو بوضع dry-run.
- مهمة وحدة بالجلسة. حدّث PROGRESS.md بآخرها.
```

## 1) شو هو النظام

مدير إعلانات ميتا متخصص بالدفع عند الاستلام (COD) لسوريا والأردن (وقابل لأسواق تانية). بيعمل:

1. **بيربط حسابات ميتا** بتسجيل دخول فيسبوك للأعمال + System User، عبر **الـ API الرسمي فقط** (ولا أتمتة متصفح، لأنها بطيئة وفيها فخاخ وبتعرّض الحساب للتقييد).
2. **بيسحب كل الأرقام** لكل إعلان، وبيأرشفها للأبد.
3. **بيطابقها مع الحقيقة من الـ OMS**: الطلب · المؤكد · المشحون · المُسلَّم · المرتجع · المحصّل.
4. **بيستلم الفيديوهات** من استديو المحتوى أو من Google Drive، بيفحص المكرر، بيسمّي، بيسجّل، وبيرفع لميتا.
5. **بيبني الحملات** من قوالب ثابتة، بإعدادات محددة بالكود (ولا إعداد تلقائي من ميتا بيمرّ بدون ما ننتبه).
6. **بيحرس الصرف** بقواعد أمان تلقائية، وبيقترح التكبير.
7. **بيرجّع الحقيقة لميتا** بأحداث CAPI (مؤكد/مُسلَّم) لتتعلّم على المشتري الحقيقي.
8. **بيحلل ويكتب** بوكلاء ذكاء اصطناعي على موديل **داخلي على السيرفر أو API خارجي** (بوابة متوافقة مع OpenAI).
9. **بيبلّغ على تيليجرام**: تقرير صباحي، أسبوعي، وتنبيهات فورية.

### 1.1 الأنظمة المربوطة (نطاق هالنسخة)
| النظام | شو بناخد | شو بنعطي |
|---|---|---|
| ميتا (Marketing API + Conversions API) | الأصول · الهيكل · الأرقام · حالات المراجعة | تغييرات معتمدة · قواعد احتياط · أحداث تحويل · رفع فيديوهات |
| OMS (crm.zakiai.io) | الطلبات برقم الإعلان وحالاتها · تكاليف المنتجات · المخزون · قدرة التأكيد | — (قراءة بس) |
| نظام الردود | قدرة الرد (رسائل بلا رد · زمن أول رد) · لقط رقم الإعلان من أول رسالة (بيوصل عبر الـ OMS) | — |
| استديو المحتوى | إبداع جاهز بوسومه (`creative.ready`) | طلب إبداعات بديلة (brief) · أداء الوسوم أسبوعياً |
| Google Drive | فيديوهات من مجلد `01_inbox` لكل منتج (مسار بديل/إضافي للاستديو) | نقل وتسمية الملفات · سجل الفيديوهات (Sheet) · تصدير اختياري |
| تيليجرام | أوامر «اوقف» فقط | تقارير · تنبيهات · روابط |

> المالية والأزمات وسيستم المنتجات والمهام: **مش بهالنسخة**. السقوف اليومية/الشهرية بيدخلها المالك بالإعدادات. خطط اختبار المنتجات بيدخلها المالك بشاشة. اترك محوّلاتهم كخادم وهمي (mock) جاهز للمستقبل.

### 1.2 شو مش شغل النظام
| مش شغله | شغل مين |
|---|---|
| إنتاج الفيديوهات والصور | استديو المحتوى |
| الرد على الرسائل واستلام الطلبات | نظام الردود والـ OMS |
| التأكيد والشحن | فريق التأكيد والـ OMS |
| أي شي بالدفع والفوترة بميتا | المالك بإيده |

## 2) المتطلبات المسبقة (قبل أي كود — «اليوم صفر»)

> هاي أهم خطوة بالمشروع. بدونها «الحقيقة» بتصير تقدير، والنظام بيفقد قيمته.

| # | المتطلب | ليش | كيف تتأكد |
|---|---|---|---|
| P0.1 | **الـ OMS بيحفظ مع كل طلب من صفحة هبوط:** `ad_id` ، `adset_id` ، `campaign_id` ، `ad_name` (من معاملات الرابط) + `fbclid` + كوكي `_fbc` و `_fbp` + الهاتف بصيغة دولية (+963 / +962) | ربط كل طلب بالإعلان والفيديو، ومطابقة أحداث CAPI | طلب تجريبي من رابط فيه المعاملات بيظهر بالـ OMS ومعه كل الحقول |
| P0.2 | **نظام الردود بيلقط من أول رسالة:** `ad_id` (ماسنجر: referral) و `source_id` + `ctwa_clid` (واتساب) وبيبعتهم مع الطلب للـ OMS | نفس السبب لحملات الرسائل | طلب تجريبي من إعلان رسائل بيوصل برقم إعلانه |
| P0.3 | **الـ OMS بيفتح API قراءة** (القسم 9.2) بتوكن خاص بالميديا باير | المزامنة كل ساعة | `GET /orders/attribution` بيرجع بيانات |
| P0.4 | **تطبيق Meta Developer** باسم النشاط ومدير الأعمال (موثّق إن أمكن) + إعداد Facebook Login for Business + System User بصلاحيات على الأصول المختارة بس | وصول رسمي وآمن | رقم التطبيق ورقم الإعداد وتوكن System User جاهزين |
| P0.5 | **حساب إعلاني تجريبي** أو حملة تجريبية بميزانية صغيرة جداً | كل تجربة تنفيذ عليه | موجود |
| P0.6 | **Google Drive:** Service Account (أو OAuth للمالك) بصلاحية Editor على مجلد المنتجات | الاستلام والتسمية | قراءة وكتابة ناجحة |
| P0.7 | **بوت تيليجرام** + رقم شات المالك | التقارير | رسالة تجريبية وصلت |
| P0.8 | **الموديلات:** سيرفر موديل داخلي (vLLM/Ollama… متوافق مع OpenAI) و/أو مفتاح API خارجي | الوكلاء | سؤال تجريبي بيرد |
| P0.9 | **أرقام كل منتج:** السعر والعروض · تكلفة الوحدة · أجور التوصيل والمرتجع لكل سوق · رسوم COD | الحاسبة | معبّاة بالإعدادات |

**URL parameters المعتمدة لكل إعلان صفحة هبوط** (بتنحط بالكود عند الإنشاء):
```
utm_source=fb&utm_medium={{site_source_name}}&utm_campaign={{campaign.id}}&utm_term={{adset.id}}&utm_content={{ad.id}}&ad_name={{ad.name}}
```
> إذا P0.1 أو P0.2 مش جاهزين: افتح مهمة بالنظام المعني بنفس اليوم. لحد ما يجهزوا، الميديا باير بيشتغل على مستوى الحملة والمنتج (إسناد بالتسمية)، وكل قرار بيطلع معلّم «تقدير».

## 3) المبادئ الثابتة (الخطوط الحمراء)

1. **الحقيقة من الـ OMS.** ولا قرار تكبير أو إيقاف على Purchase ميتا لحاله. أرقام ميتا للتشغيل اللحظي وقواعد الأمان، وأرقام الـ OMS للقرار. إذا اختلفوا، الـ OMS بيغلب والفرق بيظهر كمؤشر.
2. **الوكيل يقترح · الكود يحسب · القواعد تقرر · الإنسان يعتمد.**
3. **الأمان تلقائي، والصرف بموافقة.** إيقاف الخاسر وتخفيض الميزانية تلقائي ضمن القواعد. زيادة الصرف والإنشاء بموافقة من الموقع.
4. **كل تغيير بمجموعة تغييرات** (ChangeSet) بثماني مراحل، ومسجّل، وقابل للرجوع.
5. **حماية مزدوجة:** قواعد النظام + سقف صرف على الحساب والحملات بميتا نفسها + قواعد ميتا الآلية كاحتياط + زر إيقاف كامل.
6. **كل شي بينشأ Paused**، وبيتفعّل بعد قراءة العنصر من ميتا والتأكد إن كل إعداد مطابق للقالب.
7. **التوكنات** مشفّرة على السيرفر، ما بتوصل للمتصفح ولا لأي موديل ولا للسجلات.
8. **ولا بيانات زبائن لموديل.** أرقام مجمّعة بس. المعرّفات (هاتف مشفّر، ctwa_clid، psid، fbc/fbp) بيستخدمها كود CAPI بس.
9. **كل رقم بمصدره:** «ميتا» · «حقيقي» · «تقدير» — ظاهر جنب كل رقم.
10. **أرشفة يومية** لأن ميتا بتمسح تفاصيل قديمة وبيانات الإعلانات المحذوفة.
11. **ولا كلوكينغ، ولا تحايل** بحسابات أو مديري أعمال جداد، ولا شراء حسابات. النظام بيرفض يربط أصل مش تحت مدير أعمال المالك.
12. **ولا ادعاء ممنوع**، ولا مخاطبة الشخص بحالته الصحية، ولا قبل/بعد لمنتجات الصحة (القسم 8).
13. **ولا موافقة على صرف من تيليجرام.**
14. **ولا رفع قوائم زبائن** بلا أساس قانوني وموافقة المالك.

## 5) هيكل الحملات والتسمية

### 5.1 التسمية — العمود الفقري (إلزامية ومفروضة بالكود)
| المستوى | الشكل | مثال |
|---|---|---|
| الحملة | `{السوق}_{رمز المنتج}_{الهدف}_{المرحلة}_{YYMMDD}_C{nn}` | `SY_TRF01_WEB_CRT_261026_C01` |
| المجموعة | `{الجمهور}_{المواضع}_{رمز الصفحة}_{CPT####}_v{n}` | `BROAD_ADV_SP_CPT0012_v1` |
| الإعلان | `{CR#####}_{رمز الخطّاف}_{رمز الزاوية}_{LP#}` | `CR00147_H07_HER_LP1` |

**قاموس الرموز:**
| الخانة | الرموز |
|---|---|
| السوق | SY · JO · EG · SA · LY · MR |
| الهدف | MSG رسائل · WEB صفحة هبوط · RET إعادة استهداف |
| المرحلة | TEST اختبار منتج · CRT اختبار إبداعات · AUD اختبار جمهور · OFR اختبار عرض · SCALE تكبير |
| الجمهور | BROAD واسع · ENG تفاعل · VV مشاهدي فيديو · MSGD راسلوا وما طلبوا · LAL مشابه (بموافقة) |
| المواضع | ADV (الوحيد المتاح حالياً لحملات المبيعات) |
| الصفحة | SP صحة بلس · VP فيتا فارما · AJ أسرار الجمال (جدول بالإعدادات) |
| المفهوم | CPT#### (من سجل المفاهيم) |
| الإبداع | CR##### (رقم الفيديو بالسجل، متسلسل لكل النظام وما بيتكرر) |

- رموز المنتجات من الـ OMS، وجدول أسماء بديلة بيربط القديم (كمأة · كمأ · ماء الكمأة · KamaaEye) بنفس الرمز.
- الحملات القديمة بيقراها محلل الأسماء (H01)، والي ما بينفهم بيطلع بقائمة «بدها تسمية».
- **الصرف اليتيم** (حملة بلا رمز منتج) بيظهر كبند لحاله بالتقرير لحد ما ينربط.
- منع التكرار: قبل أي إنشاء، الكود بيفحص الاسم بالحساب. إذا موجود، `C{nn}` بيزيد.

### 5.2 أنواع الحملات للـ COD
| النوع | الهدف بميتا | وين بيصير الطلب | حدث التحسين |
|---|---|---|---|
| صفحة هبوط (الحالي عندك) | Sales · موقع التحويل: Website (Single) | نموذج الطلب بالـ OMS | Purchase على dataset الموقع |
| رسائل | Sales · موقع التحويل: Messaging apps (واتساب/ماسنجر) | المحادثة ← الردود ← OMS | المحادثات بالبداية، وبعد ما توصل ~50 حدث/أسبوع: Purchases via messaging |
| إعادة استهداف | نفس الهدف | الاتنين | نفسه |

### 5.3 القوالب (كل إعداد صريح بالكود)
**إعدادات مشتركة لكل القوالب:**
- `status = PAUSED` عند الإنشاء.
- Performance goal: Maximize number of conversions · Bid: Highest volume (Lowest cost) بدون cap.
- Conversion location: Website (Single) لصفحات الهبوط. ممنوع «Website and calls» و«Website and app».
- Product data / Catalog: **لا** (Do not use a catalog).
- Customer lifecycle: Get conversions from all audiences · Attribution model: Standard.
- الجمهور: السوق فقط · 18+ (أو حسب المنتج) · كل الأجناس إلا إذا المنتج لجنس · بدون Detailed targeting · لغات فاضية · Original audience options إذا متاح، وإلا Advantage+ audience مع Minimum age من الإعدادات · «Choose an audience for each ad creative» = Off.
- المواضع: Advantage+ · Placement value rules = No · limited spending to excluded = Off · Exclude skippable ads = On.
- Ad set budget sharing = Off (بالاختبار).
- Creative enhancements كلها Opt-out، ومنها Flex media و Optimize text per person و Website summaries.
- Multi-advertiser ads = Off.
- Related media / Advantage+ creative image generation = Off.
- URL parameters (القسم 2) على كل إعلان صفحة هبوط.
- Thumbnail مخصص (القسم 7.5).

| القالب | البنية | الميزانية | الحكم |
|---|---|---|---|
| **اختبار منتج** | حملة ABO · 3–5 مجموعات · كل مجموعة = **مفهوم واحد** فيه 3–6 تنويعات هوك | خطة المالك (مثلاً 300–400$ على 5–7 أيام لسوريا) · سقف صرف الحملة = ميزانية الاختبار | قواعد خطة الاختبار |
| **اختبار إبداعات** | حملة اختبار ثابتة لكل سوق ومنتج · مجموعة لكل مفهوم | لكل مجموعة: `B_test = max(15$, 3 × T_order)` لمدة 3–5 أيام بدون تعديل | القسم 6.4 |
| **اختبار إبداع عادل** | أداة Creative Testing من ميتا (2–5 إعلانات مختلفة) لما فيديو بعينه بدنا نقرأه | ≤ 20% من ميزانية الحملة · 7 أيام | بموافقة المالك |

### 5.4 توزيع الصفحات
- كل حملة لصفحة وحدة. المجموعات بتتوزع بالتناوب على الصفحات المعتمدة للمنتج (جدول بالإعدادات).
- رمز الصفحة بالمجموعة، فبتنقارن الصفحات بالتقرير.

### 5.5 الميزانية والمزايدة
| الخيار | متى |
|---|---|
| Lowest cost (افتراضي) | الاختبار وأول التكبير |
| Cost cap | التكبير بعد ما يثبت الرقم، وبس لما الحملة تصرف مئات الدولارات باليوم. السقف = `scaling_ceiling` محوّل لتكلفة النتيجة بميتا |
| Bid cap | حالات خاصة بقرار المالك |
| Min ROAS | بس لصفحات بتبعت قيمة الطلب |

- الجدولة بالساعات بتحتاج ميزانية إجمالية (lifetime) للمجموعة؛ القالب بيختارها لحاله إذا انطلبت.
- **توزيع البداية:** 70% تكبير · 20% اختبار · 10% جديد (قرار المالك، قابل للتعديل).

### 5.6 مرحلة التعلّم وحمايتها
- التعديل الجوهري: الاستهداف · المواضع · حدث التحسين · المزايدة · إضافة إعلان · إيقاف > 7 أيام · تغيير ميزانية كبير.

- إذا الأحداث قليلة جداً (منتج بـ 3 طلبات باليوم): النظام بيقترح حدث أعلى بالقمع أو دمج المجموعات.

## 6) الأرقام، الحاسبة، والقواعد

### 6.1 مؤشرات ميتا (تشغيل لحظي)
| المؤشر | قاعدة الاحتساب | الحقل بميتا (يتأكد بالإصدار) |
|---|---|---|
| الصرف الفعلي | `spend × (1 + fx_fee)` (افتراضي fx_fee = 1%) | spend |
| CPM | spend ÷ impressions × 1000 | cpm |
| CTR (link) | link clicks ÷ impressions × 100 | inline_link_click_ctr |
| CPC (link) | spend ÷ link clicks | — |
| التكرار | impressions ÷ reach | frequency |
| **Hook rate** | 3-second video plays ÷ impressions × 100 | actions[video_view] (يتأكد) |
| **Hold rate** | ThruPlays ÷ 3-second plays × 100 (مقام ثابت ما بيتغيّر) | video_thruplay_watched_actions |
| LPV rate | landing page views ÷ outbound (أو link) clicks × 100 | actions[landing_page_view] |
| CVR | purchases ÷ landing page views × 100 | actions[purchase] |
| CPA بكسل | spend ÷ purchases | cost_per_action_type[purchase] |
| تكلفة المحادثة | الصرف الفعلي ÷ المحادثات | — |

### 6.2 مؤشرات الحقيقة (من الـ OMS)
| المؤشر | قاعدة الاحتساب |
|---|---|
| تحويل المحادثة لطلب | الطلبات ÷ المحادثات × 100 |
| تكلفة الطلب | الصرف الفعلي ÷ الطلبات |
| نسبة التأكيد `C` | المؤكد ÷ الطلبات **الناضجة** × 100 (القسم 6.6) |
| تكلفة الطلب المؤكد | الصرف الفعلي ÷ الطلبات المؤكدة |
| نسبة التسليم `D` | المُسلَّم ÷ الشحنات × 100 |
| نسبة المرتجع | المرتجعات ÷ الشحنات × 100 |
| تكلفة الطلب المُسلَّم | الصرف الفعلي ÷ المُسلَّم |

### 6.3 الحاسبة (الربح ونقاط القرار)
| المؤشر | قاعدة الاحتساب |
|---|---|
| الصافي المحصّل | المحصّل − أجور التوصيل − أجور المرتجع |
| **حد الخسارة لكل شحنة** (`loss_limit`) | (الصافي المحصّل − تكلفة البضاعة المُسلَّمة) ÷ الشحنات |
| **سقف التكبير** (`scaling_ceiling`) | `loss_limit × 0.60` ← الهدف لتكلفة **الطلب المؤكد** |
| الربح بعد المصاريف | (الصافي المحصّل − تكلفة البضاعة المُسلَّمة − الصرف الفعلي) × `overhead_factor` إذا موجب (افتراضي 0.97 — **قرار مفتوح للمالك: شو بيمثّل الـ 3%**؛ إعداد قابل للتعديل) |
| ربح الطلب المُسلَّم | الربح بعد المصاريف ÷ المُسلَّم |
| العائد الحقيقي على الإنفاق | الصافي المحصّل ÷ الصرف الفعلي |
| المنتج الرابح | ربح الطلب المُسلَّم > 0 خلال آخر 7 أيام مكتملة التسليم |

**قبل ما يتجمع تاريخ للمنتج (أقل من 50 شحنة):** الحاسبة بتشتغل بمعادلة تقديرية من أرقام المنتج، لكل طلب (بكسل أو OMS):
```
M = C·D·P·(1−f) − C·D·G − C·S − C·(1−D)·R − K
```
P متوسط المحصّل · G تكلفة البضاعة · S الشحن · R رسوم المرتجع · f رسوم COD · K تكلفة التأكيد · C و D افتراضيات محافظة (0.65 و 0.75) لحد ما يجي رقم حقيقي.
- `T_order = min(M − profit_min, 0.6 × M)` ← هدف تكلفة **الطلب** (أو Purchase بكسل).
- `T_confirmed = T_order ÷ C` ← بيتبدّل بـ `scaling_ceiling` الحقيقي لما يصير في ≥ 50 شحنة.
- `T_delivered = T_order ÷ (C·D)`.
- إذا `M ≤ 0`: **تنبيه للمالك** — المنتج خسران بهالأسعار مهما كانت الإعلانات.
- كل الحدود بالقواعد **نسبة من T**، مش أرقام ثابتة.

### 6.4 قواعد الأمان (تلقائية من المستوى 1)
| المفتاح | الشرط الافتراضي | الإجراء | التهدئة |
|---|---|---|---|
| `rule.loser_no_orders` | صرف الإعلان ≥ 2 × T_order **و 0 طلبات بالـ OMS** (كل الحالات) بعد ≥ 48 ساعة تشغيل | إيقاف الإعلان | — |
| `rule.loser_no_confirmed` | صرف الإعلان ≥ 1.5 × scaling_ceiling **و 0 مؤكد بين الطلبات الناضجة** و ≥ 3 طلبات ناضجة | إيقاف الإعلان | — |
| `rule.high_cpa` | تكلفة الطلب المؤكد (ناضج) > scaling_ceiling بعد أول 100$ للمنتج | تخفيض المجموعة 30% أو إيقاف (إعداد) | 24 ساعة |
| `rule.high_return` | مرتجع أول 50 شحنة > 32% | إيقاف اختبار المنتج + تنبيه | — |
| `rule.daily_cap` | صرف الحساب ≥ السقف اليومي | إيقاف غير المحمي لآخر اليوم | لآخر اليوم |
| `rule.spend_spike` | صرف ساعة > 3 × متوسط الساعة آخر 7 أيام، أو صرف اليوم > 1.75 × مجموع الميزانيات اليومية | تخفيض 30% + تنبيه | 6 ساعات |
| `rule.stock_out` | أيام التغطية < 2 | إيقاف إعلانات المنتج | لحد ما يرجع |
| `rule.stock_low` | أيام التغطية < 5 | تجميد التكبير | — |
| `rule.reply_capacity` | رسائل بلا رد > الحد أو أول رد > 15 دقيقة | تخفيض حملات الرسائل 20% + تجميد التكبير | 3 ساعات |
| `rule.confirm_capacity` | غير مؤكد أقدم من 24 ساعة > الحد | تجميد التكبير | 12 ساعة |
| `rule.rejections` | 3 رفض بحساب خلال 24 ساعة | تجميد الإنشاء + تنبيه | 24 ساعة |
| `rule.stale_data` | آخر سحب ناجح (ميتا أو OMS) أقدم من ساعتين | تجميد قواعد التكبير والحقيقة | لحد ما يرجع |
| `rule.fake_orders` | ≥ 30% من طلبات إعلان وهمية/أرقام غلط (≥ 10 طلبات) | تنبيه + اقتراح إيقاف | — |

**حدود البيانات قبل أي حكم على إعلان:** Hook/Hold بعد ≥ 3,000 ظهور · CTR بعد ≥ 5,000 ظهور أو ≥ 50 نقرة · التكلفة بعد صرف ≥ 2 × T و ≥ 48 ساعة · النافذة: آخر 3 أيام **بدون اليوم الحالي** + الصرف التراكمي. قبلها الحالة «بيانات غير كافية».

**وضع «تنبيه فقط» أول 48 ساعة** لأي دفعة جديدة: القواعد بتطلع اقتراحات بالتقرير بس، إلا `daily_cap` و `spend_spike` و `stock_out` بتنفّذ فوراً.

**حالة «لم يُختبر»:** إعلان أخد < 10% من صرف مجموعته بعد 72 ساعة وصرفه < 1 × T_order → ولا إيقاف ولا «خاسر». إذا مفهومه جديد: رشّحه لـ Creative Testing.

| `scale.proof_days` | 3 |
| `scale.min_confirmed` | 5 طلبات مؤكدة ناضجة |
| الشرط | تكلفة الطلب المؤكد < scaling_ceiling لـ 3 أيام · CPA 7 أيام ≤ T · نسبة التأكيد مش أقل من متوسط المنتج |

### 6.6 الطلبات «الناضجة» (تصحيح مهم)
فريق التأكيد بيشتغل بساعات محددة (`market.team_hours`، مثلاً لحد 5 العصر)، فطلبات الليل بتتأكد ثاني يوم. **أي حساب على نسبة التأكيد أو المؤكد بيستخدم الطلبات الناضجة بس:** طلب مرّ عليه `confirm_window` (افتراضي 24 ساعة، أو أول يوم عمل كامل بعده). الطلبات الأحدث بتظهر «لسا مفتوح» وما بتدخل قواعد الإيقاف.

### 6.8 المراجع (Benchmarks)
مبدئية (ما في أرقام منشورة لسوريا والأردن، ولا تقارن بأرقام أمريكية):
- Hook (Feed): < 20% ضعيف · 20–30% عادي · ≥ 30% منيح · ≥ 40% ممتاز. الـ Reels أعلى بـ 5–7 نقاط.
- Hold: بوسيط الحساب بس (المصادر متناقضة).
- CTR (link): < 1% ضعيف · 1–2% عادي · > 2% منيح.
- LPV rate: < 70% مشكلة.

**متى تنستبدل:** لما يصير ≥ 20 فيديو كل واحد ≥ 3,000 ظهور، النظام بيحسب P25 والوسيط وP75 لكل مقياس لكل سوق ومنتج، وبيستعملهم بدل المبدئي، وبيحدّثهم أسبوعياً (جدول `Benchmark`).

## 7) الإبداعات: الاستلام، السجل، الرفع، والإطار الأول

### 7.1 مصدرين للفيديوهات
1. **استديو المحتوى:** حدث `creative.ready` (رابط + منتج + وسوم).
2. **Google Drive:** لكل منتج مجلد فيه:
   - `01_inbox` — المالك أو الفريق بيرموا فيه بأي أسماء.
   - `02_ready` — بعد الفحص والتسمية.
   - `excluded` — المكرر والمرفوض، **ممنوع حذف** أي ملف.

### 7.2 خطوات الاستلام (لكل ملف جديد) — `jobs/creative.intake`
1. نزّل الملف لتخزين مؤقت (MinIO)، وافحصه بـ ffprobe: سليم · المدة · المقاس (9:16 أو 4:5 أو 1:1) · الدقة ≥ 720p · فيه صوت · الإطار الأول مش أسود.
2. احسب **MD5**. إذا موجود بالسجل → `excluded` بسبب `md5_dup_of = CR#####` + تنبيه للمالك بالقائمة. (فحص التشابه البصري pHash **مش مطلوب** — المالك بيشيك بعينه. خلّي واجهة الدالة جاهزة ومطفية بالإعدادات.)
3. **الرقم:** `CR#####` = آخر رقم بالسجل + 1 (ما بيتكرر حتى لو انحذف إشي).
4. **اسم الملف** بالـ Drive وبمكتبة ميتا: `{PRODUCT}_CR{#####}_{أول 4 أحرف MD5}.mp4` (مثلاً `KamaaEye_CR00147_a3f9.mp4`). التسمية بتصير **جوّا Drive نفسه** فوراً، فاسم الفيديو على Drive = اسمه بميتا = اسمه بالسجل.
5. **فحص السياسات** (القسم 8): تفريغ الصوت (موديل speech-to-text داخلي إن أمكن) + النص على الشاشة (OCR) + نص الإعلان + أول شاشة من صفحة الهبوط → `policy_flag` (أخضر/أصفر/أحمر). أحمر → `excluded` بسببه. أصفر → بانتظار موافقة المالك.
6. **الوسوم** (من الاستديو، أو يعبيها المالك بشاشة، أو يقترحها وكيل M06 كمسودة): concept_id · الخطّاف · النمط · الزاوية · مستوى الوعي · اللهجة · المدة · الشكل · المصدر.
7. انقل لـ `02_ready` وسجّل.

### 7.3 السجل الدائم (جدول `CreativeAsset` + نسخة Google Sheet للمالك)
`cr_code | file_name | product_code | md5 | duration_s | aspect | resolution | source | drive_file_id | date_in | concept_id | hook_type | style | angle | awareness | dialect | policy_flag | policy_note | dup_of | status (inbox · ready · uploaded · live · paused · winner · fatigued · excluded) | meta_video_id | thumbnail_hash | ad_ids | notes`
- ممنوع حذف أي سطر. المستبعد بيضل بحالة `excluded`.

### 7.4 الرفع لميتا (بالـ API، بدون متصفح)
- رفع دفعات من `02_ready` لـ `/act_{id}/advideos` (رفع مقسّم للملفات الكبيرة؛ يتأكد من التوثيق) بنفس الاسم، وتخزين `meta_video_id`.
- انتظار حالة المعالجة `ready` قبل استعماله بإعلان.
- الإعلان بيستخدم `video_id` مباشرة (ما في بحث بالاسم، فما في خطر V14 ↔ V140).
- أي فشل رفع: إعادة بفواصل متزايدة، وبعد 5 محاولات «ميت» + تنبيه.

### 7.5 الإطار الأول والـ Thumbnail
- **الإطار الأول هو الغلاف الحقيقي** بالـ Feed والـ Reels. فحص لكل فيديو: المنتج واضح خلال ثانية · وجه أو إيد عم تستعمله · حركة بأول نص ثانية · تباين عالي · نص عربي عريض 3–6 كلمات بالمنطقة الآمنة · بلا شعار أو شاشة سودا بالبداية.
- **Thumbnail مخصص دايماً:** أقوى إطار من أول 3 ثواني (الكود بيطلّع 6 إطارات مرشحة، والوكيل M06 بيختار واحد، والمالك بيقدر يغيّر). ما نخلي ميتا تختار إطار عشوائي.
- توليد صور بالذكاء الاصطناعي: مسموح للخلفيات وتصاميم النص، **مع صورة العبوة الحقيقية**. ممنوع: عبوة مولّدة · قبل/بعد · أطباء أو زباين مولّدين.
- Hook ضعيف وجسم منيح: اقتراح 3–5 إطارات أولى بديلة كبريف للاستديو.

### 7.6 الإنتاج المستمر
- 3–8 فيديو جديد بالأسبوع لكل منتج شغّال؛ أغلبهم هوكات جديدة على جسم الفيديو الرابح.
- توزيع بعد ظهور رابحين: 60% رابحين · 30% تنويعات عليهم · 10% مفاهيم جديدة.
- نسبة الرابحين الطبيعية 4–9% من الإعلانات.
- **مفهوم جديد** = مختلف بعنصرين على الأقل من: الشخصية · المشكلة/الرسالة · الصيغة · المكان/المعالجة. تغيير النص أو اللون = تنويعة.

## 8) السياسات والحارس

### 8.1 القاعدة الذهبية
احكي عن **المنتج** ومكوناته وتراثه وطريقة استعماله، **ولا تحكي عن المشاهد وحالته**. الإعلان وصفحة الهبوط وحدة: إذا الصفحة فيها ادعاء ممنوع، الإعلان كمان معرّض للرفض.

أقسام سياسات ميتا المعنية: Health and Wellness · Personal Attributes · Unrealistic Outcomes · Unsafe Supplements · Drugs and Pharmaceuticals · Unacceptable Business Practices · Fraud, Scams and Deceptive Practices. (إعادة هيكلة Health and Wellness بتموز 2026 — الصياغة الحية بتتأكد من صفحة ميتا.)

### 8.2 أحمر (ممنوع — لا رفع)
- كلمات الشفاء والعلاج المطلق: يشفي · شفاء · علاج نهائي · يعالج · يقضي على · يزيل نهائياً · مضمون 100% · نتيجة خلال X أيام.
- ربط المنتج بمرض باسمه (الماء الأبيض · الماء الأزرق · ضعف النظر · السكري · الضغط · التهاب …).
- مخاطبة حالة المشاهد: «هل تعاني من…؟» · «عندك…؟» · «تعبت من…؟».
- مخاطبة دين أو عمر أو وضع المشاهد: «يا مسلم…» · «إذا عمرك فوق 50…».
- نص ديني بصيغة ادعاء علاجي للمنتج («وماؤها شفاء للعين» + المنتج) — ادعاء فعالية حتى لو مصدره ديني.
- اتهام المنافسين: «كل الموجود مغشوش» · «الوحيد الأصلي» بلا إثبات · «احذر المقلد» بصيغة اتهام.
- أصل أو مكوّن بلا وثيقة («ماء زمزم 100%»).
- قبل/بعد · عين مريضة أو محمرّة · مقارنة جنبية · طبيب/شهادة مولّدة · عبوة مولّدة.
- أسماء صحية بالجماهير والأحداث والروابط.
- استهداف أقل من 18 للمنتجات الصحية.

### 8.3 أصفر (بموافقة المالك)
التراث والوصفات القديمة بلا وعد علاجي · «عناية» · «روتين يومي» · «مع الاستعمال المنتظم» · ذكر مكوّن معروف كمكوّن تراثي.

### 8.4 بدائل آمنة (مكتبة قابلة للتوسّع)
| بدل | استعمل |
|---|---|
| هل تعاني من ضعف النظر؟ | قطرة ماء الكمأة، من وصفات التراث للعناية بالعين |
| عندك طنين؟ | الطنين بيزعج كتير ناس، خصوصاً بالليل |
| يشفي خلال أسبوع | تُستعمل ضمن روتين العناية اليومي |
| ماء الكمأة شفاء للعين | الكمأة، مكوّن تراثي معروف من زمان |
| علاج من الطب النبوي | من مكونات ذكرها التراث |
| بيشيل الندبات نهائياً | بيساعد يحسّن مظهر الآثار مع الاستمرار |
| احذر المقلد، كله مغشوش | عبوة مختومة ومعبأة بعناية · اطلب واستلم وادفع عند الباب |
| قبل/بعد | لقطة للعبوة وطريقة الاستعمال |
> البدائل مش مجرّبة رسمياً عند ميتا. حالة اختبار إلزامية للحارس: نص KamaaEye الحالي (فيه «وماؤها شفاءٌ للعين» و«ليس كل ما يُباع… هو الأصلي») لازم يطلع `edit` بأسبابه.

### 8.5 الإجراء
1. **الكود أولاً:** قاموس كلمات ممنوعة (عربي بكل اللهجات + تهجئات) على النص + التفريغ + OCR + الصفحة.
2. **ثم الحارس M05** للحكم السياقي: pass · edit · block.
3. صفحة الهبوط إلها فحص قبل أول إطلاق وبعد أي تعديل.

### 8.6 الرفض وسلامة الحساب
- لا إعادة رفع بلا تعديل · لا تعديل إعلان قيد المراجعة · حد أقصى لمحاولات إعادة النشر.
- رفض غلط واضح: مسودة طلب مراجعة صادقة بيبعتها المالك (Business Support Home).
- 3 رفضات/24 ساعة: تجميد الإنشاء + تنبيه.
- حساب مقيّد: المستوى بينزل لصفر + تنبيه فوري.
- الرفض المتكرر من أكبر أسباب تقييد الحسابات. فتح حسابات جديدة للهروب = مخالفة بحد ذاتها.

## 9) الربط والعقود

### 9.1 ميتا

1. «اربط فيسبوك» ← Facebook Login for Business برقم الإعداد ← رمز مؤقت للسيرفر بس ← توكن ← تشفير وحفظ.

3. الشغل الآلي: توكن System User بصلاحيات على الأصول المختارة بس.
4. فحص صحة التوكن كل 6 ساعات، وتنبيه قبل الانتهاء بـ 7 أيام، وزر إلغاء فوري.

**الصلاحيات (بأقل قدر، والأسماء بتتأكد من صفحة المطوّرين):** ads_read · ads_management · business_management · pages_show_list · pages_read_engagement · pages_manage_ads · page_events (لأحداث ماسنجر).

**العميل الآمن:**
- الإصدار من الإعدادات، وتنبيه قبل نهاية عمره بـ 90 يوم.
- قراءة عدّادات الاستخدام من الترويسات: تباطؤ عند 75%، وقوف عند 90%. الأولوية: الأمان ← القراءة ← الباقي.
- طلبات مجمّعة للقراءة، ومهام غير متزامنة (async reports) للأرقام الكبيرة.
- إعادة للأخطاء المؤقتة بفواصل متزايدة؛ ولا إعادة لأخطاء الصلاحية أو المدخلات.
- كل كتابة بمفتاح فريد + قراءة بعدها للتحقق.
- العميل بيرفض أي حقل انشال بالإصدار.

**الاستدعاءات:** الأصول · الهيكل وحقوله · Insights لكل مستوى بنافذة ثابتة (`action_attribution_windows` صريحة دايماً، لأن السحب ممكن يورث إعداد الحساب بصمت) · الحالة · الميزانية · سقف الصرف · الإنشاء من القوالب · `advideos` و `adimages` · الجماهير · `adrules_library` · `/{dataset_id}/events`.

## 17) الاختبارات

### 17.1 مثال الحقيقة — اختبار إلزامي (لازم يطلع حرفياً)
إعلان واحد: صرف 120$ · 80 محادثة · 30 طلب · 22 مؤكد · 21 شحنة · 16 مُسلَّم · 5 مرتجع · سعر 20$ · توصيل 2.5$ · تكلفة الوحدة 2.20$ · fx_fee 1% · overhead_factor 0.97.

| المؤشر | الحساب | النتيجة |
|---|---|---|
| الصرف الفعلي | 120 × 1.01 | 121.20$ |
| تكلفة المحادثة | 121.20 ÷ 80 | 1.52$ |
| تحويل المحادثة لطلب | 30 ÷ 80 | 37.5% |
| نسبة التأكيد | 22 ÷ 30 | 73.3% |
| تكلفة الطلب المؤكد | 121.20 ÷ 22 | 5.51$ |
| نسبة التسليم | 16 ÷ 21 | 76.2% |
| نسبة المرتجع | 5 ÷ 21 | 23.8% |
| الصافي المحصّل | 320 − 52.5 | 267.50$ |
| حد الخسارة لكل شحنة | (267.50 − 35.20) ÷ 21 | 11.06$ |
| سقف التكبير | 11.06 × 0.60 | 6.64$ |
| الربح بعد المصاريف | (267.50 − 35.20 − 121.20) × 0.97 | 107.77$ |
| ربح الطلب المُسلَّم | 107.77 ÷ 16 | 6.74$ |
| تكلفة الطلب المُسلَّم | 121.20 ÷ 16 | 7.58$ |
| العائد الحقيقي | 267.50 ÷ 121.20 | 2.21 |
الحكم: 5.51$ < 6.64$ ← مؤهّل لسلّم التكبير إذا ثبت 3 أيام بـ 5 مؤكد ناضج وفوق.

### 17.2 اختبارات الوحدات
