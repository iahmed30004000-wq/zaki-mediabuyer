# 06 — لوحات التحكم: كل رقم ومن وين بيجي

> النماذج: `#home` `#ads` `#ops`. الشكل: `03-look.md`. مين بيشوف: `05-permissions.md`.

## 1. القاعدة اللي ما بتنكسر

**الكود بيحسب كل رقم.** اللوحة ما فيها ولا معادلة: كل بلاطة بتقرا من loader موجود (أو دالة نقية جديدة مختبَرة بـ `src/core`). اللي بيتغيّر بهالخطة هو **الترتيب والشكل**، مش الأرقام.

- كل بلاطة (`Stat`) إلها: تسمية · نقطة المصدر (حقيقي = الـ OMS · ميتا · تقدير) · الرقم · الفرق عن أمس · «ليش؟» (قاعدة الاحتساب من `src/lib/glossary.ts`).
- الرقم الناقص «—» بسببه. أبداً صفر بدل الناقص، وأبداً رقم مخمَّن.
- اللوحة = جواب مختصر. التفصيل بضغطة: البلاطة بتودّي لمكان تفصيلها.
- الفترة: مبدّل واحد بالهيدر (اليوم · أمس · 7 أيام · مخصص)، بالرابط، بنفس `parseRange()` الموجودة. البلاطات اللي إلها نافذة ثابتة (حكم المنتج = آخر 3 أيام كاملة) بتكتب نافذتها عليها وما بتتبع المبدّل.

## 2. الرئيسية — لوحة المالك (`/`)

## 3. لوحة الإعلانات (`/ads`)

| القسم | المحتوى | المصدر |
|---|---|---|
| الصرف اليوم | الرقم · شريط السقف · «المتوقع بكرا» لو موجود | `loadToday()` + الحسابات؛ «المتوقع بكرا» من `metrics.spend_tomorrow` لآخر تشغيل لجولة الليل |
| طلبات حقيقية · تكلفة الطلب الحقيقي | مقابل أمس | `loadToday()` |
| حصة الاختبارات | النسبة مقابل الحد | `loadToday().testShare` و`.testLimit` |
| **جدول المنتجات** | المنتج · الصرف · طلبات حقيقية · تكلفة الطلب · نقطة التعادل · **الحكم** | `loadNumbers()` لنافذة «آخر 3 أيام كاملة بدون اليوم» + `getRules()` |
| آخر جولة ليل | كبّر · وقّف · تنبيهات + «افتح التقرير» | آخر `WorkflowRun` للمهمة `night-round` (`summary` و`metrics`) |
| أوامر سارية | الفعّال لمجال الإعلانات | `listOrders({ domain: "ads", active: true })` (`04` §5) |
| بنك الفيديو | لكل منتج: العدد من الهدف + كم رابح تعبان | `loadBoard()` — `src/lib/videos-board.ts` |
| مرشّحين للتكبير | أول 3 + «الكل» ← `/ads/scale` | `gatherScale()` — `src/jobs/scale-run.ts` |
| صحة البيانات | نسبة الإسناد · آخر سحب · مشاكل ← `/ads/health` | `loadDataHealth()` و`loadSafety()` — `src/lib/launch-view.ts` |

**حكم المنتج** — دالة نقية جديدة `productVerdict(cost, target, breakeven)` بـ `src/core/verdict.ts`:

| الشرط | الحكم | الشارة |
|---|---|---|
| ما في تكلفة (ما في طلبات مربوطة أو ما في صرف) | `nodata` | رمادي «ما في طلبات مربوطة» |
| `breakeven` ناقص | `norule` | رمادي «ناقص نقطة التعادل» + رابط للمنتجات |
| التكلفة ≤ `target` | `win` | أخضر «رابح — مرشّح تكبير» |
| `target` < التكلفة ≤ `breakeven` | `between` | برتقالي «بين — راقب» |
| التكلفة > `breakeven` | `lose` | أحمر «فوق التعادل» |

`target` = `rules.targetCost`، و`breakeven` = `breakevenOf(rules, code)` الموجودتين. ولا رقم مكتوب بالكود: كله من قواعد المالك. الحكم **عرض** لمنطق جولة الليل، مش قرار: القرار بيضل للجولة وللقواعد.

`/ads/campaigns`: الجدول الحالي (`loadAdsTable()`) بأعمدة افتراضية ستة: الاسم · الحالة · الصرف · طلبات حقيقية · تكلفة الطلب · الحكم. باقي الـ22 عمود بـ «أعمدة أكتر» (المنتقي الموجود، محفوظ لكل شخص).

## 4. لوحة التشغيل (`/ops`) — جديدة

| القسم | المحتوى | المصدر |
|---|---|---|
| القمع | دخل ← مؤكد ← نزل على الشحن ← انشحن ← تسلّم، وتحت كل وحدة نسبتها من اللي قبلها | `loadNumbers().totals.current`: `ordersIn` `confirmed` `shippedOrders` `delivered`؛ و«نزل على الشحن» من `metrics.landed`/`not_landed` لآخر تشغيل لفحص الشحنات (البلاطة بتنخفي لو مش موجود) |
| التسريب | الطلبات المفتوحة فوق 24 ساعة، آخر 7 أيام | `metrics.open_over_24h` لآخر تشغيل لخطة سدّ التسريب بكل يوم (دالة `metricSeries(jobKey, key, days)`) |
| فريق التأكيد | سطر لكل موظف: مسكات · مؤكد · ما ردّ · عالق +48 ساعة · الوضع | `PersonDay` الجديد (تحت) |
| المخزون | المنتج · القطع · البيع اليومي · بيكفي · المقترح للتصنيع | `StockSnapshot` (`push_stock`) + `coverUrgency()` الموجودة بـ `src/core/numbers.ts` |
| مهام التشغيل | مهام مجال `ops`: آخر نتيجة والجاي | `listWorkflows()` مفلترة `domain="ops"` |
| أوامر سارية | الفعّال للتشغيل | `listOrders({ domain: "ops", active: true })` |

**`PersonDay`** (هجرة P9) — أرقام موظف ليوم. موظفين، مش زبائن:

```prisma
model PersonDay {
  id            String   @id @default(cuid())
  actorKey      String                     // مفتاح من دليل الفريق (Actor.key)
  date          DateTime @db.Date
  claims        Int?                       // المسكات
  confirmed     Int?
  rejected      Int?
  noAnswer      Int?                       // «ما ردّ»
  noAnswerFast  Int?                       // «ما ردّ» بأقل من دقيقة
  firstClaimSec Int?                       // سرعة أول مسكة (ثواني)
  stuck48h      Int?                       // عالق فوق 48 ساعة
  reactivated   Int?
  delivered     Int?
  rejectReasons Json?                      // [{ reason, count }]
  source        String   @default("mcp")
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  @@unique([actorKey, date])
  @@index([date])
}
```

- بتتعبّى بـ `push_metrics` بصف مستواه `person`: `{ date, level: "person", id: <actorKey>, claims, confirmed, rejected, no_answer, no_answer_fast, first_claim_sec, stuck_48h, reactivated, delivered, reject_reasons }`. `id` مش معروف بدليل الفريق = الصف بينرفض مع قائمة المفاتيح المعروفة (ولا تخمين). قبل P10 الدليل هو `PEOPLE`.
- **«الوضع»** — دالة نقية `personFlag(row, teamMedian)` بـ `src/core/ops.ts`: «عالق كتير» (`stuck48h` فوق الحد) · «ما ردّ عالي» (نسبة `noAnswer/claims` فوق وسيط الفريق بهامش) · «جديد» (أقل من 3 أيام بيانات) · «منيح». الحدود إعداد (`ops.rules`) يكتبه المالك؛ ناقص = بلا شارة.
- الأسماء والأرقام بس لمين معه `ops.people`. غيره بيشوف إجمالي الفريق.

`/ops/confirm` فيها كمان: أسباب الرفض (مجموع `rejectReasons`)، وتعليق المدير اليوم (آخر `report` لمهمة تعليق المدير)، والنصايح اللي بانتظار «ابعت» (روابط لـ «بانتظارك»).
`/ops/shipping`: «ما نزلوا على الشحن» و«العالق» من أرقام تشغيلات فحص الشحنات + `ProductDay.stuck`/`returned`.
`/ops/stock`: نفس جدول اللوحة كامل + آخر تنبيه مخزون انبعت (جدول `Notification`).

## 5. صفحة المنتج (`/products/[code]`)

منتج واحد، أربع أقسام بالترتيب:

| القسم | المحتوى | المصدر |
|---|---|---|
| الإعلانات | الصرف · طلبات حقيقية · تكلفة الطلب مقابل التعادل · الحكم · الحملات الشغّالة عليه | `loadNumbers()` للمنتج + `loadAdsTable()` مفلتر |
| التشغيل | التأكيد ونسبته · أسباب الرفض · الشحن · المرتجع · العروض | بطاقة المنتج الحالية بـ `NumbersView` (الـ31 رقم بمجموعاتها) |
| المخزون والفيديو | بيكفي كم يوم · بنك الفيديو والرابحين | `StockSnapshot` + `loadBoard()` |
| اللي بيأثّر عليه | المهام اللي بتلمسه · الأوامر السارية عليه · قراراته المفتوحة | `listWorkflows()` · `listOrders({ product })` · `loadInbox()` |

`/products` = شاشة «الأرقام» الحالية كما هي بالحسابات (`loadNumbers()`): شريط الإجمالي، بطاقة لكل منتج، قارن، الفترة، شارك/طباعة. بس بمكوّنات العدّة.

## 6. اللي بيحتاجه كل قسم ليشتغل (للحالات الفاضية)

| القسم | بيحتاج | نص الحالة الفاضية |
|---|---|---|
| الصرف، الحملات | ميتا مربوطة أو Claude بيدفع (`push_metrics`) | «ما في صرف لليوم لسا — اربط ميتا من الإعدادات ← الربط» |
| الطلبات الحقيقية، التأكيد، الشحن | الـ OMS مربوط أو Claude بيدفع أرقام المنتج | «ما في طلبات لسا — بتيجي من الـ OMS» |
| فريق التأكيد | صفوف `person` | «Claude لسا ما بعت أرقام الفريق لهاليوم» |
| التسريب، نزل على الشحن | أرقام التشغيل بالمفاتيح المتفق عليها (`04` §8) | البلاطة ما بتظهر |
| خريطة المهام | `push_jobs` | «Claude لسا ما بعت خريطة مهامه — بتشوف المهام المزروعة» |
| المخزون | `push_stock` | «ما في مخزون مسجّل» |

ولا قسم بيعرض بيانات تجريبية بعد `MOCK_MODE=0`.
