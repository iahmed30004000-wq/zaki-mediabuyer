# 05 — الصلاحيات: مين بيقدر شو

> النموذج: `#perms` (توضيحي للشكل — **جدول §3 هون هو المرجع** لكل خانة). بتنبني بالمرحلة P10. قبلها الأدوار الأربعة الحالية بتضل تشتغل متل ما هي.

## 1. المبدأ

اليوم جواب «مين بيقدر شو» موزّع على أربع أنظمة:

| النظام | وين | بيحكم مين |
|---|---|---|
| أدوار المستخدمين (4 أدوار × 7 قدرات) | `src/core/roles.ts` | الناس، وللإعلانات بس |
| مستوى كل حساب إعلاني (0–3) | `src/core/autonomy.ts` + `AdAccount.autonomyLevel` | شو النظام بينفّذ لحاله على ميتا |
| لون الخطوة (أخضر · أصفر · أحمر · أسود) | `Workflow.permission` والعقد | شو الوكيل بيعمل لحاله جوّا مهمة |
| نطاقات التوكنات (`mcp` · `handoff` · `vp:read` · `vp:launch`) | `src/server/api-token.ts` | أي أدوات بيوصلها كل وكيل |

الجديد: **عرض واحد** (جدول «مين بيقدر شو») بيقرا الأربعة، **وأدوار بتغطي التشغيل والفريق**. المحرّكات الأربعة بتضل (شغّالة ومختبَرة)؛ اللي بيتوحّد هو الأسماء والشاشة والحماية.

كل خانة بالجدول وحدة من ثلاث: **لحاله** ✓ · **بموافقة المالك من الموقع** ⏳ · **ممنوع** ✕.

## 2. الناس: الأدوار

| الدور | المفتاح | لمين |
|---|---|---|
| المالك | `OWNER` (موجود) | كل شي |
| مدير | `MANAGER` (جديد) | كل شي ما عدا «للمالك بس» |
| مسؤول إعلانات | `ADS_MANAGER` (موجود) | الإعلانات: يشوف، يقترح، يوقّف، يوافق ضمن السقف |
| مسؤول تشغيل | `OPS_MANAGER` (جديد) | التشغيل: يشوف، يدير مهام الفريق، يوافق على رسايل الفريق |
| قائد فريق | `TEAM_LEAD` (جديد) | أرقام فريقه ومهامهم |
| عضو | `MEMBER` (جديد) | مهامه بس |
| محلل | `ANALYST` (موجود) | يشوف كل الأرقام ويقترح، وما بينفّذ |
| مشاهد | `VIEWER` (موجود) | يشوف اللوحات بس، بلا أرباح |

الدور قالب جاهز: المالك بيختار دور للشخص وما بيعدّل خانات. (أبسط، وكل خانة مختبَرة.)

قواعد:
- **المجال:** `work.view` و`inbox.view` بيعرضوا بس اللي من مجال القدرة التانية: اللي معه `ads.view` بيشوف مهام وقرارات الإعلانات، واللي معه `ops.view` بيشوف تبع التشغيل.
- **المصاري:** أي رقم ربح أو هامش أو تكلفة منتج أو نقطة تعادل ما بينبعت للمتصفح أصلاً لمين ما معه `money.view` (الفلترة بالسيرفر مش بالإخفاء).
- **أرقام الموظفين:** نفس الشي مع `ops.people`: بدونها الجدول بيرجع إجمالي الفريق بلا أسماء.
- **التوافق للخلف:** الأسماء القديمة السبعة بتضل مقبولة بـ `can()` لحد P10 وبتنشال فيه: `view` · `connect_meta`→`ads.connect` · `propose_change` · `pause_or_reduce`→`ads.pause` · `approve_within_cap`→`ads.approve_within_cap` · `owner_only` · `kill_switch`→`ads.pause`.

## 4. دليل الفريق والوكلاء (بيانات، مش كود)

اليوم الأسماء مكتوبة بـ `src/core/tasks.ts` (`PEOPLE`)، وأرقام تيليجرام بإعداد `notify.contacts`. الجديد جدول واحد:

```prisma
model Actor {
  id        String   @id @default(cuid())
  key       String   @unique           // "abdullah" · "claude-main" · "muse" — ثابت، وهو اللي بـ Task.assignee
  name      String                     // الاسم الظاهر (بيانات — مش بالريبو)
  kind      String                     // person | agent
  team      String?                    // management | ads | confirm | stock | video | shipping
  userId    String?  @unique           // حسابه لو إله دخول
  telegram  String?                    // رقم المحادثة للإشعارات
  active    Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

- الهجرة بتزرع السبعة الموجودين بنفس مفاتيحهم (`abdullah` `hassan` `laith` `mohammad` `hermes` `muse` `claude`) عشان `Task.assignee` القديمة تضل شغّالة، وبتنقل `notify.contacts` للعمود `telegram`.
- `PEOPLE` بيضل بالكود كقيمة احتياط لما الجدول فاضي (الاختبارات). كل الشاشات بتقرا من الجدول.
- **أي اسم موظف جديد بينكتب من شاشة الفريق، مش بالكود** (الريبو عام).
- `ApiToken.actorKey String?`: التوكن بينربط بوكيل من الدليل، فالجدول بيقول «Claude الرئيسي» مش اسم توكن.
- شاشة `/settings/team`: الناس (دعوة، دور، فريق، تيليجرام، إيقاف) · الوكلاء (توكناتهم، نطاقاتهم، آخر استعمال، سقف صرف الموديل) · جدول «مين بيقدر شو».

## 5. الوكلاء: شو كل واحد بيقدر

**النطاقات.** `mcp` (كل الأدوات) و`handoff` و`vp:*` بيضلّوا شغّالين. بينزاد نطاقات أدق للتوكنات الجديدة:

| النطاق | الأدوات |
|---|---|
| `mcp:read` | `get_rules` `get_mode` `get_approvals` `get_handoffs` `get_video_requests` `list_tasks` |
| `mcp:push` | `push_metrics` `push_stock` `push_videos` `push_jobs` |
| `mcp:run` | `log_run` |
| `mcp:ask` | `request_approval` `notify` `record_order` `end_order` |
| `mcp:tasks` | `create_task` `update_task` |
| `mcp:handoff` (= `handoff`) | `claim_handoff` `complete_handoff` `create_handoff` |
| `mcp:videos` | `claim_video_request` `complete_video_request` |

مثال: ميوز بياخد `mcp:read` + `mcp:ask` + `mcp:tasks`، فما بيقدر يدفع أرقام إعلانات. `mcp` القديم = الكل (ما بينكسر توكن شغّال).

**اللي الوكيل بيعمله لحاله.** الموقع ما بيقدر يمنع وكيل معه توكن ميتا من شي برّا الموقع. اللي بيقدر عليه: يكون **المرجع الوحيد لقواعد المالك** (`get_rules` بترجّع المستوى، القواعد، والأوامر السارية، والوكيل بيلتزم)، و**يحكم كل اللي بيمرّ منه** (ChangeSet، الموافقات، قفل `META_LIVE_VERIFIED`). الجدول بيعرض الاثنين بصدق: الخانة اللي الموقع بيفرضها عليها «✓ مفروض»، واللي هي تعليمة للوكيل عليها «تعليمة».

| العمل | من وين بتنقرا الخانة للوكيل |
|---|---|
| إيقاف/تخفيض (أمان) | مستوى الحساب (`autonomy`): لحاله من المستوى 1 |
| تكبير ضمن السقف | مستوى الحساب: بموافقة بالمستوى 1، لحاله بالمستوى 2 |
| صرف فوق السقف · حملة جديدة | دايماً بموافقة المالك (ثابت) |
| رسالة للفريق | `request_approval` بنوع `send_message`: بموافقة |
| أمر ساري | يشدّد: لحاله · يرخّي: بموافقة (ثابت) |
| دفع · شراء · تحويل · حذف · اشتراك | ممنوع (ثابت) |
| يوافق على طلبات مراجعة عند ميوز | لون الفرع بمهمة «جولة الفريق» |

## 6. الحدود الثابتة (قفل — ما بتتغيّر من أي شاشة)

1. الموافقة على أي صرف من الموقع بس، أبداً من تيليجرام.
2. ولا بيانات زبائن (اسم · هاتف · عنوان) لأي موديل ولا بأي نص بيدخل من وكيل.
3. كل حملة/إعلان بينشأ Paused، وبيتفعّل بعد التحقق.
4. ولا كتابة على ميتا بلا `META_WRITE_MODE=live` و`META_LIVE_VERIFIED=1`.
5. الصرف فوق السقف، الحملة الجديدة، القواعد، السقوف، الصلاحيات، والأمر اللي بيرخّي: للمالك بس.
6. الدفع والشراء والتحويل والحذف والاشتراك: ولا وكيل.
7. آخر مالك ما بينشال، وولا شي بينحذف نهائي (أرشفة).

بالجدول هاي الصفوف عليها قفل، وخاناتها مش أزرار.

## 7. شاشة «مين بيقدر شو»

`/settings/team` قسم ثالث. صفوف = الأعمال مجمّعة (الإعلانات · التشغيل والفريق · الشغل والنظام)، أعمدة = الأدوار ثم الوكلاء من الدليل. الخانة أيقونة بلون + كلمة عند المسّ. المصدر دالة نقية وحدة `permissionMatrix({ roles, actors, tokens, accounts, jobs })` بـ `src/core/permissions.ts` بتجمع من الأنظمة الأربعة — فالجدول دايماً بيقول الحقيقة، مش نسخة مكتوبة باليد.
اللي بيتغيّر من الشاشة (للمالك): دور الشخص · مستوى الحساب · نطاقات التوكن. كل تغيير بسجل التدقيق.

## 8. الحماية بالسيرفر

كل عنوان بيتأكد بـ `requireCapability()`. بـ P10 كل عنوان من الـ75 بياخد قدرة من الجدول الجديد:

| القدرة القديمة | العناوين | القدرة الجديدة |
|---|---|---|
| `connect_meta` | `import` `pages` | `ads.connect` |
| `kill_switch` · `pause_or_reduce` | `kill-switch` `objects/pause` | `ads.pause` |
| `propose_change` | `agents/prepare` `agents/writer` `launch` `objects/scale` `studio/links` `video-requests/[id]` `videos/request` | `ads.propose` |
| `propose_change` | `tasks` `tasks/[id]` `tasks/bulk` `tasks/merge` `ui/button` `ui/values` | `tasks.manage` (وتحديث مهمته هو: `tasks.own`) |
| `propose_change` | `workflow/[key]/run` | `work.control` |
| `view` | `ads/columns` `changes/[id]` `creatives/[code]/thumb/[n]` `rules` `studio/links` | `ads.view` |
| `view` | `approvals/pending` | `inbox.view` |
| `view` | `assistant` `assistant/chat` `consultant` | `assistant.use` |
| `view` | `done/share` `numbers/share` `export` | `money.view` |
| `view` | `mode` (قراءة) `search` | أي حساب داخل (والنتايج بتتفلتر بقدراته) |
| `view` | `tasks` (قراءة) | `tasks.own` (مهامه) أو `tasks.manage` (الكل) |
| `view` | `workflow/[key]` `workflow/[key]/versions` `workflow/live` | `work.view` |
| `owner_only` | `handoffs/[id]` | `work.control` |
| `owner_only` | `approvals/[id]` | حسب نوع القرار: صرف ← `owner_only` · `send_message` ← `ops.send` |
| `owner_only` | الباقي كله (السقوف، المستوى، التوكنات، `mode` كتابة، `numbers/paste`، `products`، `rules` كتابة، `safety-net`، `settings/[key]`، `team`، `telegram/register`، `ui`، `videos/min-spend`، `workflow` إنشاء/تعديل/تنفيذ) | `owner_only` |

والعناوين الجديدة: `inbox` ← `inbox.view` · `work/decisions` ← `work.control` · `orders` (إنشاء يشدّد) ← `orders.restrict` · `orders/[id]` (موافقة/إنهاء) ← `owner_only` · قراءات `ops/*` ← `ops.view` (+`ops.people` للأسماء).
